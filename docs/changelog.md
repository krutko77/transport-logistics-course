## 2026-09-17 — Переход с Resend на UniSender Go (юридический риск 152-ФЗ/242-ФЗ)
- Найден и обоснован юридический риск использования Resend.com (США) для
  писем с результатами теста, содержащих ФИО и должность сотрудника —
  трансграничная передача ПДн без должных оснований, риск по 242-ФЗ и
  ч.5 ст.18 152-ФЗ, потенциальный штраф по ст.13.11 ч.8 КоАП (материалы
  проверялись в соседнем проекте `website-customizer`, чек-лист 152-ФЗ и
  агент `pdn-compliance`; это инженерная оценка риска, не юридическая
  консультация — требует подтверждения юристом)
- По прямому указанию пользователя Resend полностью удалён из кода и
  зависимостей **трёх** проектов ЕС Транс: этого (test-transport-logistics),
  `es-trans-test-OM`, `es-trans-standard` (`npm uninstall resend` в каждом)
- Выбрана российская замена — **UniSender Go** (сравнивались также RuSender,
  NotiSend, Mailganer, Sendsay)
- В этом проекте `src/services/mailer.js` переписан на UniSender Go Web API
  через `fetch` (`email/send.json`). Методом проб и сверки с тестовым
  запросом из личного кабинета UniSender выяснены недокументированные явно
  детали: `apiKey` и `user_id` передаются **в теле JSON-запроса**, а не в
  заголовке `X-API-KEY`; корректный API-хост для аккаунта — `go2.unisender.ru`
  (единого хоста нет, зависит от дата-центра аккаунта; `go1` и `goapi` для
  этого аккаунта не подходят — возвращают `User not found`/`Api key mismatch`)
- `.env` заполнен реальными `UNISENDER_GO_API_KEY`, `UNISENDER_GO_USER_ID`,
  `UNISENDER_GO_API_URL`, `UNISENDER_GO_FROM` (ключ вписан пользователем
  напрямую в файл, без пересылки в чат — по явной просьбе пользователя)
- Домен отправки `es-trans.pro` подтверждён в UniSender Go (включая DKIM).
  Настроен поддомен `unisender.es-trans.pro` как домен ссылок (NS-делегирование
  на uns1/2/3.unisender.com), но на конец сессии он ещё в статусе «Ожидание
  настройки DNS» — из-за этого реальная отправка пока падает с
  `code 229: Custom backend domain or tracking domain required for sending`
- Два других проекта (`es-trans-test-OM`, `es-trans-standard`) переведены на
  актуальный способ деплоя `vibe-deploy-service` (созданы `.vibe-deploy.json`
  с их реальными доменами `test-1.es-trans.ru` и `test-2.es-trans.ru`
  соответственно) — раньше использовали неактуальный `deploy.sh` с пустыми
  `SERVER_ID`/`VIBE_API_KEY`. Все три проекта передеплоены и подтверждены
  пользователем как открывающиеся в браузере (код без Resend уже в проде)
- Перенос UniSender Go в `es-trans-test-OM`/`es-trans-standard` **отложен**
  до подтверждения рабочей отправки здесь — см. `docs/state.md`
