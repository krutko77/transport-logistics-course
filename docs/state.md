# Состояние проекта

**Последнее обновление:** 2026-09-14

## Где мы сейчас
Проект «Тест по курсу «Транспортная логистика»» задеплоен и работает на
`https://test-logistics.es-trans.ru/`. Синхронизирован с GitHub-репозиторием
`https://github.com/krutko77/transport-logistics-course.git` (ветка `main`).
Банк вопросов — 50 вопросов, `VARIANTS` пересобраны без пересечений (см.
прошлые сессии); эти изменения уже закоммичены (3 локальных коммита впереди
`origin/main`, ещё не запушены).

Недоставка письма руководителю **подтверждена**: пользователь прошёл тест
на самом домене (прод), письмо на `kpv@es-trans.pro` не пришло — то есть
дело не в dev-контейнере, а именно в проде. Рабочая гипотеза (блокировка
SMTP-порта на стороне хостинга) подтвердилась. Пользователь отправил запрос
в поддержку Timeweb с диагностикой (текст вопроса подготовлен и отправлен) —
**ответ пока не получен**.

Параллельно внесена правка по независимому запросу пользователя: на экране
результатов теста и в письме руководителю вопросы нумеровались исходным
`id` из банка вопросов (1, 2, 3, 4, 5, 11, 12…), а не порядковым номером по
ходу теста. Исправлено на порядковую нумерацию 1–25 в трёх местах:
- `src/public/js/test.js` — экран результата (`${i + 1}` вместо `${q.id}`)
- `src/routes/results.js` — добавлено поле `questionNumber` при сборке
  результата (`i + 1`), `questionId` оставлен как есть
- `src/services/mailer.js` — колонка "№" в письме руководителю использует
  `questionNumber` вместо `questionId`

Эти три файла проверены (`node --check`), но **ещё не закоммичены**.

## Сейчас в работе
1. Ждём ответ от техподдержки Timeweb по блокировке SMTP-порта на проде.
2. Правки нумерации вопросов (см. выше) — в рабочей копии, не закоммичены
   и не задеплоены.
3. 3 локальных коммита с прошлых сессий (банк вопросов 50, VARIANTS без
   пересечений) не запушены в `origin/main`.

## Следующие шаги
1. **Снять ответ от Timeweb** по блокировке SMTP-порта (587) на проде.
   - Если разблокируют — писем через SMTP должно быть достаточно, отдельно
     проверить повторным прохождением теста на домене.
   - Если откажут/долго не отвечают — переключаться на Resend (создать
     API-ключ на resend.com, вписать в `.env` как `RESEND_API_KEY`; код уже
     поддерживает оба пути и сам предпочтёт Resend, если ключ задан —
     менять код не нужно).
2. Закоммитить правки нумерации вопросов (`test.js`, `results.js`,
   `mailer.js`) и задеплоить вместе с ранее не задеплоенными изменениями
   банка вопросов — командой
   `curl -X POST http://172.30.0.1:8191/deploy -d '{"project": "test-transport-logistics"}'`
   после коммита (и по возможности push в GitHub).
3. После деплоя — попросить пользователя пройти тест ещё раз на проде и
   проверить: (а) новую нумерацию 1–25 на экране результата, (б) не пришло
   ли наконец письмо (если Timeweb уже ответили и разблокировали порт).
4. **Важно:** в `.env` в открытом виде лежит реальный пароль от почтового
   ящика `test@es-trans.pro` (`SMTP_PASS`). Файл не в git и не отслеживается,
   но именно такая утечка уже случалась раньше на этом проекте (см.
   `vscode-portal-doctor/docs/incident-transport-logistics-course-deploy-and-leaked-root-password.md`).
   Пользователь пока попросил пароль не трогать — но стоит поднять вопрос
   ротации/переноса в секрет-хранилище при следующей возможности.
