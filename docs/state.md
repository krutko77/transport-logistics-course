# Состояние проекта

**Последнее обновление:** 2026-09-13

## Где мы сейчас
Проект «Тест по курсу «Транспортная логистика»» задеплоен и работает на
`https://test-logistics.es-trans.ru/`. Синхронизирован с GitHub-репозиторием
`https://github.com/krutko77/transport-logistics-course.git` (ветка `main`).
Банк из 45 вопросов разбит на 5 реальных тематических блоков курса. Тест
состоит из 2 вариантов по 25 вопросов (по 5 из каждого блока), которые вместе
покрывают весь банк из 45 вопросов без пропусков — при повторном прохождении
подставляется следующий вариант. Порядок вариантов ответа (А/Б/В/Г)
перемешивается динамически при каждом показе вопроса. Приём результатов
переведён на сравнение по тексту ответа (`answerTexts`), а не по индексу —
из-за клиентской рандомизации порядка. Деплой — через `vibe-deploy-service`,
SSL выпущен автоматически при первом деплое. Визуально проект приведён к
корпоративному стилю ЕС Транс: логотип и favicon перенесены из
`es-trans-test-OM`, акцентный цвет сменён с красного на синий (`#0098DD`).

По жалобе сотрудника на то, что вопросы поверхностны по сравнению с курсом,
банк вопросов углублён: часть вопросов переведена в кейсовый/расчётный формат
(объёмный вес, компенсация CMR, тариф, масса ТС и т.д.), выровнена длина
формулировок вариантов (убрано угадывание по объёму текста), пересчитано
распределение правильных ответов по А/Б/В/Г (11/10/12/12 из 45 — ровно).
Изменения задеплоены на прод.

## Сейчас в работе
Активная разработка приостановлена сразу после деплоя обновлённого банка
вопросов. Изменения запушены в git и переданы в `vibe-deploy-service`
(ответ 200, `firstRun: false`), но визуально на самом домене
`test-logistics.es-trans.ru` пользователем ещё не подтверждены — с рабочего
контейнера прямой curl-доступ к публичному домену заблокирован файрволом
(ожидаемое поведение), поэтому проверка возможна только через браузер
пользователя.

## Следующие шаги
- Попросить пользователя открыть `https://test-logistics.es-trans.ru/`
  (с жёстким обновлением Ctrl+F5) и подтвердить, что новые кейсовые/расчётные
  вопросы отображаются корректно и тест ощущается сложнее.
- Пройти тест на проде до конца и подтвердить: результат сохраняется в
  `data/results/` на сервере и письмо доходит до `MANAGER_EMAIL`
  (`RESEND_API_KEY` намеренно оставлен пустым — используется SMTP fallback).
- При необходимости — донастроить `RESEND_API_KEY`/`RESEND_FROM`, если
  пользователь решит перейти на Resend вместо SMTP.
- Дальнейшие правки дизайна/вопросов (если будут) — вносить через тот же цикл:
  правка → коммит → push → `curl -X POST http://172.30.0.1:8191/deploy -d '{"project": "test-transport-logistics"}'`.
