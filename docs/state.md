# Состояние проекта

**Последнее обновление:** 2026-09-18

## Где мы сейчас
Проект «Тест по курсу «Транспортная логистика»» задеплоен и работает на
`https://test-logistics.es-trans.ru/`. Синхронизирован с GitHub-репозиторием
`https://github.com/krutko77/transport-logistics-course.git` (ветка `main`,
локально 5 коммитов впереди `origin/main`, ещё не запушены).

Эта сессия не трогала логику письма/UniSender — занимались чисткой
документации для Клода. `CLAUDE.md` этого проекта был приведён в порядок
(убрано дублирование разделов, весь Б24/VibeCode-контент — проект реально
не подключён к Битрикс24, письмо переведено с исторического Resend на
актуальный UniSender Go). По просьбе пользователя аналогичная чистка
перенесена ещё на два проекта ЕС Транс — `es-trans_test_standard_MOO` и
`es-trans_test_GFD_MOO`: у обоих убран весь Б24/VibeCode-шаблонный контент
(протокол онбординга, ключи VibeCode, MCP-серверы, Битрикс24 iframe и
т.д.) — пользователь лично подтвердил, что ключи под эти проекты не
выдавались и интеграция в Б24 не настроена, несмотря на то что в их коде
остались нетронутые файлы `src/check.js` и `src/utils/api.js`, технически
написанные под VibeCode API (остаточный шаблонный код, не отражающий
реальное использование — решение по нему не принималось). Раздел
Email-сервиса в этих двух файлах переписан под их реальный код — SMTP через
`nodemailer` (не Resend, не UniSender Go: перенос на UniSender Go в них
ещё не делался, см. ниже). Четвёртый проект, `es-trans_tests-results`,
пропущен — у него вообще нет `CLAUDE.md`, создание нового файла не входило
в задачу «почистить».

Технический статус email-провайдера (не менялся в этой сессии, перенесён
из прошлой записи): письма в проверенном виде уходят через **UniSender
Go** — раньше использовались Resend.com (США) и SMTP (Timeweb), оба
признаны проблемными (Resend — юридический риск по 152-ФЗ/242-ФЗ при
передаче ПДн сотрудников за рубеж; SMTP-порт был заблокирован на проде
хостингом). В этом проекте `src/services/mailer.js` уже переписан на
UniSender Go Web API (`fetch` на
`{UNISENDER_GO_API_URL}/ru/transactional/api/v1/email/send.json`, ключ и
`user_id` передаются в теле JSON, не в заголовке). `.env` заполнен:
`UNISENDER_GO_API_KEY`, `UNISENDER_GO_USER_ID=8343054`,
`UNISENDER_GO_API_URL=https://go2.unisender.ru`, `UNISENDER_GO_FROM`.
Домен отправки `es-trans.pro` подтверждён в UniSender Go (DKIM тоже).

**Отправка писем по-прежнему не подтверждена рабочей** — на конец прошлой
сессии (2026-09-17) блокером был домен ссылок (tracking domain)
`unisender.es-trans.pro` в статусе «Ожидание настройки DNS», из-за чего
API возвращал `code 229`. В этой сессии статус домена не перепроверялся.

   ссылок → `unisender.es-trans.pro`). Как только статус сменится с

     `curl -X POST http://localhost:3000/api/results -H "Content-Type: application/json" -d '{"name":"...","position":"...","answerTexts":[...],"questionIds":[...],"variantNum":1}'`
     (важно: контракт ждёт `answerTexts` — тексты ответов, не индексы!)
