## Ключевые решения
- Не переделывать движок теста под multiple-choice/сопоставление (вариант 6
  из предложенных) — слишком большой объём работы и риск регрессии ради
  одного из пяти направлений; пользователь подтвердил, что достаточно
  углубить контент в текущем формате
- Кейсы/расчёты делать точечно (8–12 вопросов), только там, где в банке уже
  есть чёткая формула или цифра — чтобы не придумывать недостоверные данные
  вне материала курса
- ID и структуру `VARIANTS` не трогать, если новые отдельные вопросы не
  потребовались — меньше риска сломать покрытие банка вариантами
- Playwright для визуальной проверки ставить временно (`--no-save`) и удалять
  после — держать зависимости проекта чистыми
