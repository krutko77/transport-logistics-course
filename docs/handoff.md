# Передача проекта

Этот файл нужен, чтобы новый исполнитель (человек или нейронка) за 5 минут
понял, что это за проект, что в нём работает и что делать дальше.

## Снимок передачи

**Дата снимка:** 2026-09-13

**Что за проект:** Тест по курсу «Транспортная логистика» — сотрудник проходит
тест по ссылке, результаты сохраняются на сервере и отправляются руководителю
на почту. Исходный материал — открытые экзаменационные вопросы, разбитые
на 5 реальных тематических блоков курса.

**Что работает прямо сейчас:**
- Задеплоено и доступно по адресу `https://test-logistics.es-trans.ru/`
  (HTTPS, SSL выпущен автоматически, без предупреждений браузера)
- Express-сервер (`src/server.js`), фронтенд-SPA (`src/public`)
- Банк вопросов (`src/data/questions.js`) — **50 вопросов** на проде сейчас
  (45 задеплоенных ранее + правки этой сессии, которые ещё НЕ задеплоены,
  см. ниже). Вопрос про себестоимость/маржу (id 38) усложнён, добавлено ещё
  5 новых вопросов на ту же и смежные темы (id 46–50)
- 2 варианта теста по 25 вопросов; структура пересобрана в этой сессии — с
  прода они пока покрывают банк с 5 намеренными дублями (старая версия из
  git), в рабочей копии — уже без единого пересечения (см. "В процессе")
- Приём результатов и оценка по тексту ответа (`src/routes/results.js`,
  контракт `answerTexts` + `questionIds`, не индексы); результат теста
  сохраняется в `data/results/*.json` на сервере **независимо** от того,
  ушло письмо или нет
- Отправка результата на почту (`src/services/mailer.js`, Resend → SMTP
  fallback; `RESEND_API_KEY` намеренно пуст — работает SMTP через
  `smtp.timeweb.ru`). SMTP-логин/пароль проверены из dev-контейнера —
  авторизация и реальная отправка писем работают
- Брендинг ЕС Транс: логотип и favicon, акцентный цвет — синий
  (`#0098DD`/`#0080BB`)
- Git-репозиторий синхронизирован с GitHub
  `https://github.com/krutko77/transport-logistics-course.git`, ветка `main`

**Что в процессе / недоделано:**
- **Изменения этой сессии НЕ закоммичены и НЕ задеплоены**: правки
  `src/data/questions.js` (банк 45→50) и `src/public/js/test.js` (VARIANTS
  без пересечений) лежат только в рабочей копии (`git status` покажет их как
  modified) — нужно закоммитить и передеплоить
- Пользователь сообщил, что письмо с результатом теста не пришло на
  `kpv@es-trans.pro`. Диагностика: SMTP технически исправен (проверено из
  dev-контейнера), но неясно, работает ли он с прод-сервера — там порт может
  быть заблокирован (см. "Частые ошибки" в CLAUDE.md). Пользователя попросили
  пройти тест ещё раз на самом домене — **ответ ещё не получен**, это первое,
  что нужно узнать в следующей сессии
- В `.env` в открытом виде лежит реальный пароль от `test@es-trans.pro`
  (`SMTP_PASS`). Не в git, но пользователь просил пока не трогать (сначала
  разобраться с недоставкой) — стоит вернуться к вопросу ротации

**Где живёт прод:** `https://test-logistics.es-trans.ru/`, деплой через
`vibe-deploy-service` (порт 3100, slug `krutko77-test-transport-logistics`).

**Главные подводные камни:**
- Деплоить строго через
  `curl -X POST http://172.30.0.1:8191/deploy -H "Content-Type: application/json" -d '{"project": "test-transport-logistics"}'`
  — никогда не по SSH (файрвол намеренно блокирует прямой доступ хосту,
  таймауты — ожидаемое поведение, не поломка)
- С рабочего контейнера нельзя проверить прод обычным curl (тот же файрвол
  блокирует исходящий доступ к публичному IP хоста) — проверка сайта и
  сквозного прохождения теста возможна только через браузер пользователя
- Контракт `POST /api/results` ожидает `answerTexts` (тексты) + `questionIds`,
  а не индексы ответов — из-за клиентской рандомизации порядка А/Б/В/Г;
  при правке фронтенда это нужно сохранить
- Если новых вопросов больше, чем нужно для замены дублей (или наоборот) —
  сейчас правило проекта: **без пересечений между вариантами вообще**,
  дублей быть не должно (изменено в этой сессии, раньше допускались)
- SMTP-настройки могут работать из dev-контейнера, но не работать на проде
  (или наоборот) — не считать проверку из контейнера окончательной
- `.env` содержит реальный пароль в открытом виде — обращаться аккуратно, не
  выводить целиком в чат/логи
- После правок статики (CSS/HTML/логотип) браузер может закэшировать старые
  файлы — проверять через жёсткое обновление (Ctrl+F5)
- `.claude/` в `.gitignore` — команды и настройки MCP не попадают в git-снимки
