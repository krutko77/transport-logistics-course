# Передача проекта

Этот файл нужен, чтобы новый исполнитель (человек или нейронка) за 5 минут
понял, что это за проект, что в нём работает и что делать дальше.

## Снимок передачи

**Дата снимка:** 2026-09-12

**Что за проект:** Тест по курсу «Транспортная логистика» — сотрудник проходит
тест по ссылке, результаты сохраняются на сервере и отправляются руководителю
на почту. Исходный материал — 45 открытых экзаменационных вопросов, разбитых
на 5 реальных тематических блоков курса.

**Что работает прямо сейчас:**
- Задеплоено и доступно по адресу `https://test-logistics.es-trans.ru/`
  (HTTPS, SSL выпущен автоматически, без предупреждений браузера — подтверждено
  пользователем скриншотами)
- Express-сервер (`src/server.js`), фронтенд-SPA (`src/public`)
- Банк из 45 вопросов (`src/data/questions.js`), 5 реальных блоков курса
  (id 1–10, 11–20, 21–27, 28–36, 37–45)
- 2 варианта теста по 25 вопросов (по 5 из каждого блока), вместе покрывающие
  все 45 вопросов банка без пропусков; при провале/повторной попытке
  подставляется следующий вариант
- Динамическая рандомизация порядка ответов А/Б/В/Г при каждом показе вопроса
- Приём результатов и оценка по тексту ответа (`src/routes/results.js`,
  контракт `answerTexts` + `questionIds`, не индексы)
- Отправка результата на почту (`src/services/mailer.js`, Resend → SMTP
  fallback; `RESEND_API_KEY` намеренно пуст — работает SMTP)
- Брендинг ЕС Транс: логотип и favicon (перенесены из `es-trans-test-OM`),
  акцентный цвет — синий (`#0098DD`/`#0080BB`)
- Git-репозиторий синхронизирован с GitHub
  `https://github.com/krutko77/transport-logistics-course.git`, ветка `main`,
  все изменения запушены

**Что в процессе / недоделано:**
- Полный цикл на проде (пройти тест → результат сохраняется на сервере →
  письмо доходит руководителю через SMTP fallback) пользователем явно ещё
  не подтверждён
- Текущая синяя цветовая схема — по образцу со скриншота пользователя,
  финальное подтверждение "устраивает" ещё не получено

**Где живёт прод:** `https://test-logistics.es-trans.ru/`, деплой через
`vibe-deploy-service` (порт 3100, slug `krutko77-test-transport-logistics`).

**Главные подводные камни:**
- Деплоить строго через
  `curl -X POST http://172.30.0.1:8191/deploy -H "Content-Type: application/json" -d '{"project": "test-transport-logistics"}'`
  — никогда не по SSH (файрвол намеренно блокирует прямой доступ хосту,
  таймауты — ожидаемое поведение, не поломка)
- Контракт `POST /api/results` ожидает `answerTexts` (тексты) + `questionIds`,
  а не индексы ответов — из-за клиентской рандомизации порядка А/Б/В/Г;
  при правке фронтенда это нужно сохранить
- Пользователь иногда присылает скриншоты ДРУГИХ проектов
  (`es-trans-test-OM`, тест "Стандарт работы") как образец дизайна — сверять,
  что конкретно переносить, а не весь экран
- После правок статики (CSS/HTML/логотип) браузер может закэшировать старые
  файлы — проверять через жёсткое обновление (Ctrl+F5)
- `.claude/` в `.gitignore` — команды и настройки MCP не попадают в git-снимки
- Правильные ответы должны быть равномерно распределены по А/Б/В/Г — при
  добавлении новых вопросов пересчитывать распределение

**Первое, что стоит сделать:** подтвердить у пользователя устраивающую
цветовую схему и пройти тест на проде до конца, чтобы убедиться в письме
руководителю.
