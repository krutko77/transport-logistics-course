# Передача проекта

Этот файл нужен, чтобы новый исполнитель (человек или нейронка) за 5 минут
понял, что это за проект, что в нём работает и что делать дальше.

## Снимок передачи

**Дата снимка:** 2026-09-18

**Что за проект:** Тест по курсу «Транспортная логистика» — сотрудник проходит
тест по ссылке, результаты сохраняются на сервере и отправляются руководителю
на почту. Исходный материал — открытые экзаменационные вопросы, разбитые
на 5 реальных тематических блоков курса.

**Что работает прямо сейчас:**
- Задеплоено и доступно по адресу `https://test-logistics.es-trans.ru/`
  (HTTPS, SSL выпущен автоматически, без предупреждений браузера)
- Express-сервер (`src/server.js`), фронтенд-SPA (`src/public`)
- Банк вопросов (`src/data/questions.js`) — 50 вопросов, `VARIANTS` в
  `src/public/js/test.js` без пересечений (2 варианта по 25 вопросов
  покрывают все 50)
- Приём результатов и оценка по тексту ответа (`src/routes/results.js`,
  контракт `answerTexts` + `questionIds`, не индексы); результат теста
  сохраняется в `data/results/*.json` на сервере **независимо** от того,
  ушло письмо или нет
- Git-репозиторий синхронизирован с GitHub
  `https://github.com/krutko77/transport-logistics-course.git`, ветка `main`
  (5 локальных коммитов впереди `origin/main`, ещё не запушены)

**Что в процессе / недоделано:**
- **Смена email-провайдера в разгаре** (не двигалась в последней сессии).
  Resend.com признан юридически рискованным для писем с ПДн сотрудников
  (152-ФЗ/242-ФЗ) и полностью удалён из кода/зависимостей этого и ещё двух
  проектов ЕС Транс (`es-trans_test_standard_MOO`, `es-trans_test_GFD_MOO`).
  Взамен подключается **UniSender Go** (РФ)
- В этом проекте `src/services/mailer.js` уже переписан на UniSender Go Web
  API, `.env` заполнен реальными ключами. Но **письма пока не уходят**:
  UniSender Go возвращает `code 229 "Custom backend domain or tracking
  domain required for sending"`, потому что домен ссылок
  `unisender.es-trans.pro` ещё не завершил активацию (NS-делегирование
  прописано, статус на 2026-09-17 — «Ожидание настройки DNS», не
  перепроверялся с тех пор)
- Изменения `mailer.js`/`package.json`/`.env.example` в этом проекте **не
  закоммичены** — лежат в рабочей копии до подтверждения, что письмо реально
  доходит
- `es-trans_test_standard_MOO` и `es-trans_test_GFD_MOO` пока только
  избавились от Resend (SMTP там как единственный путь); перенос на
  UniSender Go в них ещё не делался
- **Новое в этой сессии:** `CLAUDE.md` во всех трёх проектах почищен от
  дублирования и Б24/VibeCode-шаблонного контента (см.
  `docs/changelog.md` за 2026-09-18). Правки в
  `es-trans_test_standard_MOO`/`es-trans_test_GFD_MOO` лежат в их рабочих
  копиях и не закоммичены — коммит этой сессии сделан только в текущем
  проекте
- В `.env` в открытом виде лежит реальный пароль от `test@es-trans.pro`
  (`SMTP_PASS`). Не в git, но пользователь просил пока не трогать — стоит
  вернуться к вопросу ротации

**Где живёт прод:** `https://test-logistics.es-trans.ru/`, деплой через
`vibe-deploy-service`. Аналогично: `es-trans_test_standard_MOO` →
`https://test-1.es-trans.ru/`, `es-trans_test_GFD_MOO` →
`https://test-2.es-trans.ru/` (у обоих `.vibe-deploy.json` с этими
доменами).

**Главные подводные камни:**
- Деплоить строго через
  `curl -X POST http://172.30.0.1:8191/deploy -H "Content-Type: application/json" -d '{"project": "<имя_проекта>"}'`
  — никогда не по SSH (файрвол намеренно блокирует прямой доступ хосту,
  таймауты — ожидаемое поведение, не поломка)
- С рабочего контейнера нельзя проверить прод обычным curl (тот же файрвол) —
  проверка сайта и сквозного прохождения теста возможна только через браузер
  пользователя
- Контракт `POST /api/results` ожидает `answerTexts` (тексты) + `questionIds`,
  а не индексы ответов — из-за клиентской рандомизации порядка А/Б/В/Г
- Правило проекта: **без пересечений между вариантами вообще** — дублей
  вопросов между `VARIANTS` быть не должно
- UniSender Go Web API: ключ и `user_id` передаются **в теле JSON-запроса**,
  а не в заголовке `X-API-KEY` — иначе будет вводящая в заблуждение ошибка
  `Api key mismatch`/`User not found`
- API-хост UniSender Go индивидуален для аккаунта (для этого — `go2.unisender.ru`,
  не `go1`/`goapi`) — не хардкодить по документации, только через `.env`
- Домен ссылок (tracking domain) в UniSender Go обязателен для отправки, даже
  если письмо не содержит трекаемых ссылок — без него `code 229`
- `.env` содержит реальные секреты (SMTP-пароль, API-ключ UniSender Go) —
  не выводить целиком в чат/логи; новые ключи пользователь вписывает в `.env`
  сам, без пересылки в чат
- `.claude/` в `.gitignore` — команды и настройки MCP не попадают в git-снимки
- 5 локальных коммитов не запушены в `origin/main` — не забыть `git push`
- В `es-trans_test_standard_MOO`/`es-trans_test_GFD_MOO` в коде остались
  файлы `check.js`/`utils/api.js`, технически реализующие VibeCode API —
  подтверждено пользователем, что реального Б24-подключения там нет
  (ключи не выдавались), но сам код не удалялся — это отдельная задача,
  не относящаяся к чистке `CLAUDE.md`

`unisender.es-trans.pro` в личном кабинете UniSender Go (Настройки → Домены

прошла, закоммитить изменения и переносить схему на
`es-trans_test_standard_MOO` и `es-trans_test_GFD_MOO`. Отдельно —
