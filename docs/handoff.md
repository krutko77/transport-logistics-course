## Снимок передачи

**Дата снимка:** 2026-09-19

**Что за проект:** Тест по курсу «Транспортная логистика» — сотрудник проходит
тест по ссылке, результаты сохраняются на сервере и отправляются руководителю
на почту. Исходный материал — открытые экзаменационные вопросы, разбитые
на 5 реальных тематических блоков курса.

**Что работает прямо сейчас:**
- Задеплоено и доступно по адресу `https://test-logistics.es-trans.ru/`
  (HTTPS, SSL выпущен автоматически, без предупреждений браузера; повторный
  деплой проверен в этой сессии, `firstRun:false`, порт 3100)
- Express-сервер (`src/server.js`), фронтенд-SPA (`src/public`)
- Банк вопросов (`src/data/questions.js`) — 50 вопросов, `VARIANTS` в
  `src/public/js/test.js` без пересечений (2 варианта по 25 вопросов
  покрывают все 50)
- Приём результатов и оценка по тексту ответа (`src/routes/results.js`,
  контракт `answerTexts` + `questionIds`, не индексы); результат теста
  сохраняется в `data/results/*.json` на сервере **независимо** от того,
  ушло письмо или нет
- **Доставка писем через UniSender Go подтверждена рабочей** — домен ссылок
  `unisender.es-trans.pro` активирован, тестовое письмо дошло до
  `kpv@es-trans.pro`. Блокер `code 229` снят
- Соседние проекты `es-trans_test_standard_MOO` (`test-2.es-trans.ru`) и
  `es-trans_test_GFD_MOO` (`test-1.es-trans.ru`) тоже на UniSender Go,
  задеплоены и отвечают 200 — конфликт доменов из-за переименования папок

`https://test-1.es-trans.ru/`.

**Главные подводные камни:**
- Деплоить строго через
  `curl -X POST http://172.30.0.1:8191/deploy -H "Content-Type: application/json" -d '{"project": "<имя_папки_проекта>"}'`
  — никогда не по SSH (файрвол намеренно блокирует прямой доступ хосту,
  таймауты — ожидаемое поведение, не поломка)
- `vibe-deploy-service` матчит проект по **имени папки на диске**, а не по
  слагу на портале — переименование папки без синхронизации
  `registry.json` на портале ломает привязку домена (это уже случалось,
  решалось несколько сессий, снято администратором 2026-09-19)
- С рабочего контейнера нельзя проверить прод обычным curl (тот же файрвол) —
  проверка сайта и сквозного прохождения теста возможна только через браузер
  пользователя
- Контракт `POST /api/results` ожидает `answerTexts` (тексты) + `questionIds`,
  а не индексы ответов — из-за клиентской рандомизации порядка А/Б/В/Г
- Правило проекта: **без пересечений между вариантами вообще** — дублей
  вопросов между `VARIANTS` быть не должно
- UniSender Go Web API: ключ и `user_id` передаются **в теле JSON-запроса**,
  а не в заголовке `X-API-KEY` — иначе будет вводящая в заблуждение ошибка
  `Api key mismatch`/`User not found`
- API-хост UniSender Go индивидуален для аккаунта (для этого — `go2.unisender.ru`,
  не `go1`/`goapi`) — не хардкодить по документации, только через `.env`
- Домен ссылок (tracking domain) в UniSender Go обязателен для отправки, даже
  если письмо не содержит трекаемых ссылок — без него `code 229`
- `.env` содержит реальные секреты (SMTP-пароль, API-ключ UniSender Go) —
  не выводить целиком в чат/логи; новые ключи пользователь вписывает в `.env`
  сам, без пересылки в чат
- Секреты нельзя вставлять в `docs/*.md` даже как историческую справку —
  GitHub push protection уже блокировал пуш из-за этого раньше на этом
  проекте (ключ Resend в тексте `state.md`)
- `.claude/` в `.gitignore` — команды и настройки MCP не попадают в git-снимки
