# Запрос администратору портала: перепривязка домена после переименования папки проекта

**От кого:** Клод, работающий в контейнере студента `krutko77`, проект
`es-trans_test_transport_logistics` (тест по курсу «Транспортная логистика»).

**Дата:** 2026-09-19

## Суть проблемы

В контейнере студента папка проекта была переименована с `es-trans-test-OM`
на `es-trans_test_GFD_MOO` (тот же проект, тот же код, просто новое имя
директории). `vibe-deploy-service`, судя по всему, связывает домен с
проектом по имени папки/слагу, а не по стабильному внутреннему ID — после
переименования папки сервис перестал находить проект под обоими именами:

```bash
curl -X POST http://172.30.0.1:8191/deploy \
  -H "Content-Type: application/json" \
  -d '{"project": "es-trans_test_GFD_MOO"}'
# → {"error":"domain test-1.es-trans.ru уже занят проектом krutko77::es-trans-test-OM"}

curl -X POST http://172.30.0.1:8191/deploy \
  -H "Content-Type: application/json" \
  -d '{"project": "es-trans-test-OM"}'
# → {"error":"no such project: es-trans-test-OM"}
```

То есть регистрация домена `test-1.es-trans.ru` в системе всё ещё указывает
на слаг `krutko77::es-trans-test-OM`, а физической папки с таким именем на
диске студента больше нет — деплой в тупике: старый слаг недостижим (нет
папки), новый слаг недоступен (домен занят старым).

## Что нужно сделать

Обновить внутреннюю регистрацию `vibe-deploy-service`, чтобы домен
`test-1.es-trans.ru` был привязан к слагу `krutko77::es-trans_test_GFD_MOO`
вместо `krutko77::es-trans-test-OM`. Конкретный способ зависит от того, как
устроено хранилище привязок на вашей стороне — видимо, один из:

1. Переименовать существующую запись проекта `es-trans-test-OM` →
   `es-trans_test_GFD_MOO`, сохранив привязку к домену и сертификат
   Let's Encrypt (чтобы не выпускать заново).
2. Либо удалить устаревшую запись `es-trans-test-OM` (если она гарантированно
   не используется — проект физически переименован, старой папки не
   существует) и позволить `es-trans_test_GFD_MOO` пройти обычный первый
   деплой на домен `test-1.es-trans.ru`.

## Похожая ситуация, вероятно, есть и со вторым проектом

Есть подозрение (не подтверждено пользователем на момент этого запроса),
что аналогичная история — с другим проектом:

```bash
curl -X POST http://172.30.0.1:8191/deploy \
  -H "Content-Type: application/json" \
  -d '{"project": "es-trans_test_standard_MOO"}'
# → {"error":"domain test-2.es-trans.ru уже занят проектом krutko77::es-trans-standard"}
```

Домен `test-2.es-trans.ru` привязан к слагу `krutko77::es-trans-standard`, а
папка в контейнере студента называется `es-trans_test_standard_MOO`. Прежде
чем чинить эту привязку, стоит уточнить у пользователя (владельца портала/
студента), действительно ли это тот же проект под новым именем — в отличие
от случая с `es-trans-test-OM`, здесь это пока не подтверждено явно.

## Проверка после исправления

После обновления привязки должен успешно пройти обычный запрос из
контейнера студента:

```bash
curl -X POST http://172.30.0.1:8191/deploy \
  -H "Content-Type: application/json" \
  -d '{"project": "es-trans_test_GFD_MOO"}'
```

Ожидаемый ответ — успешный деплой на `test-1.es-trans.ru` без ошибки о
занятом домене.
